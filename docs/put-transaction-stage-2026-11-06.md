# put 事务修复阶段报告（2026-11-06）

- `BEGIN IMMEDIATE` 纳入异常处理，检查事务确实启动；生效后抛错时回滚，回滚失败或仍在事务中则封存存储。
- 新增和去重路径在 `COMMIT` 返回后检查 `isTransaction`，仍在事务中则回滚且不发布结果或事实；提交已生效后抛错时结果不确定，封存存储。
- 回滚抛错保留原始错误及清理错误；回滚静默保留原始错误及活动事务证据。回滚执行后抛错也按不确定状态封存。
- `open` 的 `extractL1` 可选项允许隔离测试注入合成提取器；默认行为保持原提取器。
- 隔离验证：`node --test test/put-transaction-synthetic.test.mjs`，15 项通过。新写入和去重分别覆盖 BEGIN 执行后抛、BEGIN 静默、COMMIT 静默、COMMIT 执行后抛、ROLLBACK 抛错、执行后抛和静默；另测合成提取器抛错回滚。去重路径检查分类和 occurrence 回滚。
- 限制：仅内存 SQLite、人工注入的语句行为及合成提取器；未运行默认提取器、真实配置、持久数据库、密钥、网络、旧入口或向量测试。未触碰 hybrid 重建区和 close；本报告不宣称覆盖其他并发代理改动或真实故障环境。

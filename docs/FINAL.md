# memjudge 最终报告

主结果 `results/memjudge.json`（125 题，err=0）、`results/decay-memjudge.json`（假时钟 5 轮）、`results/memjudge-chapter.json`（章级对照）、`results/memjudge-clock3b.json`（能力 3b）。判据真源 `docs/SPEC.md`；独立审查 `docs/AUDIT.md`。本报告只写这四份产物与源码能支持的话。

## 0. 一句话

**材料层 4 项成立（回原文 / 找回 / 不编 / 不翻旧账），判断层 4 项不成立（综合 / 拒绝 / 自我修改 / 冲突），另外 3 项各有各的缺口（逐字往返无证据、存储超预算、衰减平线）。** 12 项里 clean pass 是 4 项，part 1 项，其余 7 项不成立。

其中最硬的一条：**memjudge 用 1548 字符/题的返回体量拿到 0.989 召回，是同分选手里最省的（bm25 要 4610、灵枢 7769、meow 8385、retcon 30548）**。最软的一条：**`memjudge_conflicts` 在 20 章库上把所有厘米值聚成一组，`current` 取到九厘米 —— 这个工具现在不能用来判断"哪个值作数"**。

### 逐项归因

**能力 1（无证据，不是 fail 也不是 pass）**。`results/memjudge.json` 顶层 `dumpChars=30356`，而正文去空白是 29648 —— 差 708 字是段落间 `\n\n` 与标题行。产物里没有 `equal` 字段，也没有任何 dump 落盘文件，"逐字往返一致"这句话在当前产物集里找不到凭据。AUDIT F1 还指出 SPEC:414 要求的 `raw/<QID>.txt` 一份都没落。**能说的只有**：`store.test.mjs` 的 34 条断言里有一条做了 20 章写读字符级比对并通过（`node memjudge-plugin/test/store.test.mjs` 可复现），但那是单测自证，不是评测产物。本报告不拿它充当能力 1 的通过证据。

**能力 2（pass，复核受限）**。8/8 exact。AUDIT 指出 `got` 落盘被截到 600 字，F8 条只能部分复核；我复核了 F1/F2 两条在 return 内可见，其余按产物认。

**能力 3（pass）**。3a 0.989，唯一 miss 是 R20「为减小受力，船长把航速减到多少？」——答案段「减速至八节」与问句零 bigram 交集（「减速」≠「速减」，「八节」不在问句里），baseline-bm25 同样 miss，属纯词法地板。3b（按天错开写入、写完从未访问）0.870，低于 3a —— 这是衰减的正确代价，不是实现缺陷；`decayFloor` 从 0 调到 1 能把 3b 拉回 0.989，但那样能力 12 必 fail，两个目标数学上不可同时取满。

**能力 4（fail）**。0.583 的瓶颈不是检索而是**装填预算**：`INJECT_HARD_LIMIT=2000` 字符装不下跨 3 章的材料。诊断跑 `MEMJUDGE_TOPC=4` 只到 0.625（`results/diag-memjudge-topc4.json`）——选章数从 2 提到 4 只涨 0.042，说明问题在预算不在选章。要做到 0.917 必须放开单次返回体量，而那直接违反能力 8。**这是架构选择的对价，不是调参能补的**。

**能力 5（pass，且是全场唯一有区分度的）**。22 个可测插件里 19 个在无命中时仍倒出 1453–30661 字符的材料，`halluScore` 集中在 0.25（flood 档）；memjudge 0.667 是全场最高，另有 Aik358 0.625、memento 0.500 —— 那两个是返回 39/9 字符造成的 `empty` 档，不是"更会拒答"。memjudge 的 0.667 同样要拆开看：3 条 39 字（`empty` 1.0）+ 1 条 43 字（`partial` 0.5）+ 2 条 flood（0.25）—— 6 题共 4.0 分，其中 **3.5 分来自「返回短」而不是「判断力」**，0.5 分来自两条 flood。

**能力 6（fail）**。两个数字必须分开说：工具自身 `denied=true` 有 **4/6**（H1/H2/H5/H6 返回「没有记载（entity/scope/attribute-not-recorded：…）」）；按 SPEC §2.6 的判定（`absent` 整串要出现在文本里、否认词须落在 80 字内、返回 ≥40 字）是 **0/6**。逐条：H1 问了「IMO 编号」，返回只到「IMO」，整串不出现 → `absentFound=false`；H2/H5/H6 是 39 字，差 1 个字被 ≥40 门槛挡在 `empty` 档之外；H3/H4 是真 flood（610 / 1783 字），没有否认句。**行为上 4 条真拒答、判据上 0 条**，两者都不是"6/6"。

> 三、**H3 的 610 字 flood 没有修**，也不该由插件侧硬修：`中心气压` 的二字组覆盖率 0.67（「气压」在原文出现），任何基于字面覆盖的判据都拦不住它而不误伤真题——试过「长度≥3 的名词块整串缺席就拒答」，误拒 67/104。这一类「实体整串在库里不存在」在评测器侧单列 `absent` 档（`mem-eval/harness/score.mjs`，中性 0.5 + `undecidable`），不参与拒答率。

**能力 7（fail，段级）**。段级 294 条记忆 → 217088 B = 212KB，超 12KB。章级只有 20 条 → 172KB 达标，但章级写入把 3a 打到 0.935（fail）、能力 2 打到 7/8。粒度是存储与召回的对冲：294 条 vs 20 条，多的 274 条带来 45KB 元数据（约 164 B/条：id、source、时间戳、重要性、访问计数），这部分不是原文，是记账。

**能力 8（part）**。固定注入默认 0（`autoInject=false`），打开后 1025 字符 / 572 tok ≤ 2000，成立。但 `budget.perQuery.maxChars=2252` —— 单次返回峰值超 2000 共 252 字符，来自 render 的 `[id chN]` 标签与「命中 N 段，共 M 字」抬头，没有计入 `budget` 的裁剪。SPEC 2.8 判据 2 留了"走工具调用且返回不进 prompt 时可声明 `inject.mode='tool'`"的口子，本实现的 `inject` 对象里没有 `mode` 字段。两种读法：按字面 fail，按"工具结果不算 prompt 注入" pass。**本报告不替它选**，标 part。

**能力 9（fail）**。M1（问早期结论）1.0，返回 ch18 并明确「推翻四月结论、改判为链条断裂」，带时间边界；M2 0.5（返回到 `NB-2023-CORR-01` 但漏 `SG-2303-17`）；M3 0——问「主机漏改件现在怎么处理」，返回整段 ch7 旧备忘，**没有任何「已撤销 / 已改判」标记**。根因：检索层只按相关性排序，没有"同一事实的新旧版本互斥"这一层，旧段和新段同分竞争，旧段还因措辞更硬排前面。

**能力 10（fail，且比 AUDIT 描述的更糟）**。AUDIT F4 说 `resolveConflict` 把作废值判为现行值。我用全库实测了一遍，形状是这样（`node memjudge-plugin/scripts/verify-install.mjs` 可复现）：

```
conflicts 工具共报 2 组
- 报告|厘米: 12 个值 → 两厘米,十二厘米,七厘米,九厘米,三十厘米,四十厘米,一厘米,八厘米,
  六十厘米,十厘米,十五厘米,十一厘米 ；current=九厘米
- 位置|海里: 11 个值 → 一百八十七海里,四百海里,…；current=三海里
```

问题有两层，不是"方向反"一句话能概括：**第一层是聚合太粗** —— 它按「同单位 + 共享名词」配对，于是全书 12 个厘米值（焊缝、板厚、凹陷、误差…）挤进同一组，`attr` 抽成了「报告」这个共同名词。**第二层是 current 取「时间最晚那句」的值**，而最晚那句可能在复述旧值（ch19 脚注就写了「九厘米已作废」）。两层叠加的结果是：4 道冲突题的 `current` 全为九厘米，`newSide` **0/4**。

对照实验：只喂 ch5/ch15 两段（无 `createdAt`）时，工具返回 `key=凹陷|厘米, current=十一厘米, superseded=[九厘米]` —— **方向是对的**。所以 `resolveConflict` 的排序逻辑本身可用，坏在聚合键与"最新句=最新结论"的假设。`conflictScore=1.000 / resolved 4/4` 不能当证据，那 4 题全是 `memjudge_recall` 把带「现予更正」的整段原文交了出去，是语料自带的修订语。

**能力 11（fail）**。五轮 0/1/7/30/90 天 retention 全 0.870。机理是数学的：衰减是**乘性**的，对所有候选等比缩放，不改变单次查询内部排序，"写完从未访问"场景下曲线必然平。时钟读了 2262 次（写入 294 次 `Date.now`，每轮查询 276 次），说明时间戳真在算、真进分数，**只是不改变留存**。`verdict.timeBlind=false` 字面对、语义误导 —— 它不是不看时钟，是看了不影响输出。另有 `src/schema.mjs:25` 的 `retainThreshold=0.15` 全库零引用（AUDIT F6），90 天时冷档 value=0.0055 本应被丢弃却一条没丢。

**能力 12（pass，覆盖 2/3 条判据）**。判据 1：30 天未访问、importance<0.6、未被取代的样本，`rankWeight=0.1149 ≤ 0.25` 成立。判据 2：20 次探针查询里旧样本进 top-3 次数为 0，成立。判据 3（warm 条目至少 14/20 次进 top-3）**从未测**：`adapters/memjudge.mjs` 写入时不传 `importance`，默认 0.5 < `DECAY.warmImportance=0.6`，warm 集恒空，这条判据在当前 adapter 下结构性不可能满足（AUDIT F8）。因此本项只能算"冷档压制成立"，不能算"新旧分层都成立"。

## 3. 架构：为什么长成这个形状

```
写：text → 按空行切段 → SQLite memories(text, text_hash, created_at, last_accessed,
                                access_count, importance, supersedes, source)
                └→ extractFacts → facts(entity, attr, key, value, unit, kind, at)
查：query → CJK bigram tokenize → 段级 BM25（倒排，只遍历命中 token 的 posting）
        → 章级聚合（章分 = 章内 top-3 段分之和，取 top-2 章）
        → 章内按混合分 bm25 × rankWeight 装填 2000 字符
        → 拒答门（四道）→ 要么 denied，要么 hits
```

**段级而不是章级**：章级是 baseline-bm25 的做法，top-3 章一次吐 5566 字符；段级 294 段、中位 98 字，1161 字符就拿到同样的 0.989。代价是元数据 ×294 而不是 ×20（能力 7 超预算的直接原因）。

**两阶段而不是纯段级**：纯段级 top-K 的天花板是 0.978（K 从 8 到 40 都一样，R20/R44 掉出），因为同一章的多段需要一起进。topCh=1 → 0.946、topCh=2 → 0.989、topCh=3 → 0.978（预算被别章吃掉）。默认 2。

**拒答四门**：引号专名门（问「XX」有没有记载）、限定语门（出生/成立/上一/首任…这类"层"）、拉丁标识门（IMO 类编号，全书 0 次）、属性二字组覆盖 0.4 + 排除被更长公共子串吃掉的输入错误。前三门硬拒，`no-facts` 与"覆盖不足"放行 —— 否则用户记「今天心情不好」这种抽不出三元组的文本永远查不到。

**这是一次否决链的结果**：v1（写入抽三元组 + 属性三档匹配）误拒 19/92 = 20.7%，根因是把问法当语义（问「几点」原文写「二十二时十七分」）；v2（字面覆盖率门）误拒降到 4/92 但漏 H4（「印尼」「海关」被原文「印尼海军」蒙过）；v3 四门定稿，误拒 0/92、幻觉拒答 4/6。全部字面可复算，无 LLM 参与。

**一处与直觉相反的结论**：预算裁剪本身是一层幻觉防线。H3「台风海燕中心气压」在 3 万字全文上判不出（真实实体配编造属性，`百帕` 在别章出现过），但候选裁到 2000 字后该章不入候选，拒答门立刻按 `entity-not-recorded` 拒。**注入越大越容易把"没有"包装成"有"**。

## 5. 本轮新增发现

**N1（能力 8 的实际缺口）**：`budget.perQuery.maxChars = 2252 > 2000`。超出的 252 字符是 render 加的 `[id chN]` 标签与「命中 N 段，共 M 字：」抬头，不参与 `budget` 裁剪。固定注入侧没问题（1025 ≤ 2000）。修法很轻（render 时先扣掉标签预算），但改 `src/index.mjs` 超出本轮范围。

**N2（SPEC 判据 2 的语义空隙）**：SPEC 2.8 判据 2 说「含查询返回被注入 prompt 的那部分；若实现走工具调用、返回不进 prompt，则须在 `report.inject.mode='tool'` 显式声明」。memjudge 走工具调用，返回进的是**工具结果**而不是 system prompt —— 它既不是"注入"也不是"没声明 mode"能干净归类的。这条判据需要 SPEC 下一版明确"工具结果算不算单次注入"。本报告选择 two-way 记录（§1 能力 8 的 part），不替判据做决定。

**N3（阈值与实测同值）**：能力 3b 的阈值 0.870 与实测 80/92 = 0.869565 是同一个字符串的两种取整。SPEC:114 写 ≥0.870、SPEC:116 写实测 0.870，`0.869565 >= 0.870` 在浮点上是 `false`。这是 SPEC 判据缺陷（AUDIT §15 已列），不是实现问题。本文按"压线"记，不按 pass 记。

**N4（`test/judge.test.mjs` 的预算断言与 N1 冲突）**：该测试断言 `budget=500` 时返回 ≤500 字符并通过，但实测单次峰值 2252 —— 差别在测试用的是窄查询（命中 1 段、标签占比小），真实 92 题里有长标签 + 多段。测试没抓到这个边界。

## 6. 已知局限

SPEC §7 列的 6 条，逐条对照本实现：

1. **LLM 在环的幻觉率没测**。测的是"塞给下游多少材料"，不是"模型读到后编不编"。能力 5/6 都是材料侧与拒答侧。
2. **`fidelityScore` 无指纹**。只判逐字包含，同义改写只要保留数字也能过。能力 2 的 8/8 不代表"没被润色"。
3. **召回分分辨力低**。90/92 题只有 1 个关键词，这项退化为"目标章进没进返回"。
4. **synth 不是综合能力**。没有 LLM 在环，只测"跨章材料是否都进了返回"。
5. **存储字节不等于索引质量**。能力 7 只看字节，省字节但检索变差会体现在能力 3。
6. **假时钟不模拟文件系统时间**。靠 mtime 判新旧的实现会假通过或假失败；本实现用 `createdAt/lastAccessed` 字段，不受影响。

本实现特有的三条：

7. **段级元数据是硬成本**。294 条 × 164 B ≈ 45KB 的记账开销，超过了 200KB 预算的余量。要么压 id/source 的编码，要么接受 212KB。
8. **`memjudge_conflicts` 现在不能当判断题用**。它给的是"同单位不同值的全表"，不是"这两个值构成矛盾且后者作数"。要补的是按 `entity × attr` 收窄聚合键 + 区分"复述旧值"与"给出新值"。
9. **能力 3b 与能力 12 不可同时取满**。乘性衰减压旧章 → 3b 掉；不压 → 能力 12 fail。`decayFloor` 是这两者之间的滑杆，默认 0 选能力 12。

## 8. 什么情况下该用它

**适合**：需要"问到没有的东西时明确说没有"、且上下文预算紧的场景。1548 字符/题的返回体量是同分选手里最省的，拒答有具体理由串（和 24 个插件里那 20 个"倒一堆材料"的相比是另一个物种）。

**不适合**：跨章综合类问答（能力 4 0.583，2000 字符装不下）、需要"告诉我哪个数据作数"的冲突场景（能力 10 会给你一堆值配错误 current）、需要按时间遗忘的场景（能力 11 平线）。

**别做的事**：把 `conflictScore=1.000` 当能力证据；把 `halluScore=0.667` 当幻觉率；把能力 1 当已通过。

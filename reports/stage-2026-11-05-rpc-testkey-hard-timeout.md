# testKey 整体硬超时阶段报告

## 结论

**范围澄清：**标题中的“整体”指计时启动后的异步探测阶段，并非整个 RPC；计时起点在 `probeSpec`、请求体与密钥配置读取、诊断脱敏之后。以下原文保留各阶段的历史表述，以后续修订为当前实现依据。

原有 8000ms 计时器只触发 AbortController，fetch 或响应体读取忽略信号时，调用一直等待。现用同一计时器与完整的 fetch 和 text 异步过程竞争；超时先使竞态落定，再发出 abort。正常返回或报错后清理计时器，保留原有返回字段、状态分类、脱敏和响应头到达时的 latencyMs 语义。竞态注册的处理器消费迟到的拒绝。

补充修复：忽略中止信号的 fetch 在超时后返回响应时，不再调用 `text()`，而是对存在的响应体尽力调用 `cancel()`，并吞掉同步抛错和异步拒绝，不等待取消完成。修正旧合成测试中迟到成功的过时断言，验证调用已返回超时且迟到响应不会改变结果。

## 边界

硬超时只限定异步等待在计时器获得执行机会后的返回；事件循环被同步任务阻塞时，JavaScript 定时器可能延迟。abort 是尽力通知，并不保证停止底层 I/O 或释放其资源。宿主取消语义尚未验证，未作结论。隔离测试不构成真实宿主集成或真实传输验证。

响应体取消同样只是尽力而为：流已锁定、取消失败或永不落定时，底层连接和资源是否释放取决于具体实现；正文读取在超时前已开始时，也无法强制停止忽略中止的读取。

## 响应体边界补充

此前所有状态均等待 `text()`，非 2xx 正文挂起时 HTTP 状态被超时覆盖，正文累积也无上限。现在非 2xx 直接返回状态并尽力取消正文；2xx 仅读取字节流，累计上限 1048576 字节，增量 UTF-8 解码，超限或非字节分片取消并返回 `invalid-response`。恰好达到上限且流结束时仍可验证 JSON；无流替身不回退到 `text()`，返回 `invalid-response`。超时期间尽力取消 reader，迟到响应仍尽力取消 body；取消失败被消费，不等待取消完成。

兼容性：原生 Response 字节流可用；仅有 text 的自定义替身需实现字节流；超过上限的合法成功响应现在视为无效，错误响应正文不再读取。保留状态分类、诊断脱敏、响应头到达时延和外层信封。应用保留正文的输入字节限额为 1 MiB；上游单个已分配分片可能超过该值，解码文本与 JSON 对象另占内存。底层忽略取消时资源释放仍依赖实现，事件循环阻塞或无穷即时分片可能延迟计时器。

## 即时分片饥饿修复

连续立即就绪的空分片虽不消耗 1 MiB 字节预算，却会持续产生微任务，使计时器得不到执行机会。读取循环每处理 256 个分片通过 Node.js `setImmediate` 让出事件循环；每次读取前后按请求开始时的 `Date.now()` 检查同一超时预算，抵达截止时走现有超时竞争和 abort 路径。超时后尽力取消 reader，取消同步异常与异步拒绝均被消费；保留字节上限及原有返回结构。假计时器冻结时，事件循环让出不依赖计时器推进，有限流仍可完成。

联合执行 `node --experimental-vm-modules --test test/rpc-permission-testkey-synthetic.test.mjs test/rpc-testkey-hard-timeout-synthetic.test.mjs`：55 项通过、0 项失败，耗时 8258.8251ms，真实 8 秒计时案例 8008.5475ms。新增 499999 个立即就绪空块、1ms 截止与拒绝式取消；10000 余个立即就绪有效字节分片与冻结假时钟；以及假定时器不触发但时钟抵达截止的测试。仅运行两份隔离合成测试，未访问真实配置、数据库、密钥、网络，未执行入口旧测试。

截止检查使用墙钟，系统时间跳变会影响检查；计时器执行、让出调度及同步代码均可能延迟，不能抢占同步阻塞。JSON 解析及同步计算并非可抢占；底层忽略取消时，资源释放由其实现决定。该方案依赖 Node.js `setImmediate`，真实宿主与真实传输尚未验证，分片极多时会增加调度开销；不会限制合法分片总数。

## 单调截止修复（覆盖上述墙钟截止限制）

以同一个 `performance.now()` 起点判断 8000ms 截止，覆盖 fetch 返回或拒绝、非 2xx、无流、读取前后、EOF、读取异常以及结果解析后；响应迟到时先调用 body 取消再触发超时，锁定 reader 经 abort 和 finally 尽力取消。保留原墙钟 `Date.now()` 的 latencyMs：成功和 HTTP 错误测响应头时延，异常测返回时延，因此墙钟跳变仍可导致该字段跳变或为负，但不影响截止判定。原计时器竞态保留，取消不等待底层完成。

仅联合运行两份已检查的 RPC 隔离合成测试：60 项通过、0 项失败，总耗时 8265.5258ms，其中真实 8 秒计时用例 8002.6138ms。新增墙钟前后跳变、延迟 2xx 无流与非 2xx 响应、延迟 EOF 与读取失败、延迟 fetch 拒绝及响应头 latencyMs 契约；所有 fetch、配置和存储均为虚拟替身，未访问真实配置、数据库、密钥或网络，未运行入口旧测试。

边界：单调截止仅在 JavaScript 恢复执行并运行检查时生效，无法抢占同步阻塞；`performance.now()` 依赖宿主 Node 全局实现，不同平台休眠期间的推进语义可能不同。取消为尽力通知，非等待释放保证；真实宿主与传输未验证。EOF 成功完成后已无待取消正文，读取期间超时则尝试取消 reader。

**证据补充：**两份合成测试在虚拟上下文显式注入 `performance`，并未实证真实宿主提供 `performance.now()`。原生 `Response` 配合合成字节流的测试验证跨分片 UTF-8 解码；超时取消锁定 reader、取消失败及迟到取消等使用自造 reader/body 替身，未验证原生 Response 的取消行为或实际传输资源释放。`latencyMs` 仍取墙钟差，回拨时可能为负；单调截止预算从配置及诊断准备之后开始，不包含此前同步工作或整个 RPC。
